# Power BI Data Model and DAX Measures

This document specifies the exact Power BI data model (tables, relationships,
cardinalities, filter directions) and every DAX measure/calculated column
needed to build `powerbi/GenAI_Adoption_Intelligence.pbix` by hand in Power BI
Desktop, per `powerbi/BUILD_INSTRUCTIONS.md`. This file was written and
DAX-reviewed alongside `src/analysis.py` and `sql/02_adoption_metrics.sql` so
all three implementations of each metric agree — but the actual `.pbix` was
intentionally **not** generated by an AI agent (see BUILD_INSTRUCTIONS.md for
why) and this DAX has not been executed inside a live Power BI session.

**SYNTHETIC DATA ONLY.** Every measure that touches `estimated_minutes_saved`
carries the same disclaimer as elsewhere in this project: modeled assumption,
not validated ROI.

---

## 1. Tables (loaded from `data/processed/clean_*.csv`)

| Power BI table name | Source file | Role |
|---|---|---|
| `Users` | `clean_users.csv` | Dimension (also carries per-user calculated columns — see §3) |
| `Business_Unit` | Reference query off `Users[business_unit]`, deduplicated | Dimension |
| `Role` | Reference query off `Users[role]`, deduplicated | Dimension |
| `Feature_Catalog` | `clean_feature_catalog.csv` + 1 appended "Unknown / Not Captured" row | Dimension |
| `Calendar` | `clean_calendar.csv` | Date dimension — **Mark as date table** on `Calendar[date]` |
| `Usage_Events` | `clean_usage_events.csv` | Fact (finest grain — one row per event) |
| `Feedback` | `clean_feedback.csv` | Fact |
| `Training_Sessions` | `clean_training_sessions.csv` | Fact (session-level grain — see `docs/data_model.md`) |

## 2. Relationships

| From (many) | To (one) | Cardinality | Cross-filter direction | Active? |
|---|---|---|---|---|
| `Users[business_unit]` | `Business_Unit[business_unit_name]` | Many-to-one | Single (Business_Unit → Users) | Active |
| `Users[role]` | `Role[role_name]` | Many-to-one | Single (Role → Users) | Active |
| `Usage_Events[user_id]` | `Users[user_id]` | Many-to-one | Single (Users → Usage_Events) | Active |
| `Feedback[user_id]` | `Users[user_id]` | Many-to-one | Single (Users → Feedback) | Active |
| `Usage_Events[feature_name]` | `Feature_Catalog[feature_name]` | Many-to-one | Single (Feature_Catalog → Usage_Events) | Active |
| `Feedback[feature_name]` | `Feature_Catalog[feature_name]` | Many-to-one | Single (Feature_Catalog → Feedback) | Active |
| `Training_Sessions[business_unit]` | `Business_Unit[business_unit_name]` | Many-to-one | Single (Business_Unit → Training_Sessions) | Active |
| `Usage_Events[event_date]` * | `Calendar[date]` | Many-to-one | Single (Calendar → Usage_Events) | Active |
| `Feedback[feedback_date]` * | `Calendar[date]` | Many-to-one | Single (Calendar → Feedback) | Active |
| `Training_Sessions[session_date]` | `Calendar[date]` | Many-to-one | Single (Calendar → Training_Sessions) | Active |
| `Users[assigned_access_date]` | `Calendar[date]` | Many-to-one | Single (Calendar → Users) | Active |

\* `event_date` / `feedback_date` are calculated columns
(`= DATEVALUE(Usage_Events[event_timestamp])`, same pattern for Feedback)
added because `Calendar[date]` is a pure date column while
`event_timestamp`/`feedback_timestamp` are datetimes — Power BI relationships
need matching granularity.

**All relationships filter in a single direction, dimension → fact**, per
star-schema best practice (no bidirectional/both-direction relationships and
no many-to-many anywhere in this model). Because `Calendar[date]` relates to
four different tables (`Usage_Events`, `Feedback`, `Training_Sessions`,
`Users`) on four *different* date columns, all four relationships can be
simultaneously active — there is no conflict, since each is a separate table.

**Technical/hidden fields:** hide `event_id`, `feedback_id`,
`training_session_id`, `session_id`, and `feature_id` from report view
(right-click column → Hide in Report View). They exist for uniqueness and
troubleshooting only, not for slicing.

## 3. Calculated columns (build these on `Users` first — several measures depend on them)

```dax
Is Eligible =
Users[eligible_for_access_flag] = TRUE() && NOT ISBLANK(Users[assigned_access_date])
```

```dax
Completed Training = NOT ISBLANK(Users[training_completed_date])
```

```dax
Used Prompt Library =
CALCULATE(COUNTROWS(Usage_Events), Usage_Events[feature_name] = "Prompt Library") > 0
```

```dax
Meaningful Actions Within 14 Days =
VAR AccessDate = Users[assigned_access_date]
RETURN
IF(
    ISBLANK(AccessDate),
    BLANK(),
    CALCULATE(
        COUNTROWS(Usage_Events),
        Usage_Events[event_type] IN {"prompt_submitted", "output_generated", "feature_completed", "output_exported"},
        Usage_Events[event_timestamp] >= AccessDate,
        Usage_Events[event_timestamp] <= AccessDate + 14
    )
)
```

```dax
Is Activated =
Users[Is Eligible]
    && (Users[Completed Training] || Users[Used Prompt Library])
    && Users[Meaningful Actions Within 14 Days] >= 3
```

```dax
First Value Timestamp =
CALCULATE(
    MIN(Usage_Events[event_timestamp]),
    Usage_Events[event_type] IN {"feature_completed", "output_exported", "output_generated"},
    Usage_Events[successful_completion_flag] = TRUE()
)
```

```dax
Hours To Value =
IF(
    ISBLANK(Users[First Value Timestamp]) || ISBLANK(Users[assigned_access_date])
        || Users[First Value Timestamp] < Users[assigned_access_date],
    BLANK(),
    DATEDIFF(Users[assigned_access_date], Users[First Value Timestamp], HOUR)
)
```

```dax
Activation Week =
VAR FirstMeaningfulTs =
    CALCULATE(
        MIN(Usage_Events[event_timestamp]),
        Usage_Events[event_type] IN {"prompt_submitted", "output_generated", "feature_completed", "output_exported"}
    )
RETURN
IF(
    ISBLANK(FirstMeaningfulTs),
    BLANK(),
    LOOKUPVALUE(Calendar[week_number], Calendar[date], DATEVALUE(FirstMeaningfulTs))
)
```

## 4. Measures

All ratio measures use `DIVIDE()` (never bare `/`) so a zero or blank
denominator returns blank instead of an error.

```dax
Eligible Users = CALCULATE(COUNTROWS(Users), Users[Is Eligible] = TRUE())
```

```dax
Activated Users = CALCULATE(COUNTROWS(Users), Users[Is Activated] = TRUE())
```

```dax
Activation Rate = DIVIDE([Activated Users], [Eligible Users])
```

```dax
WAU =
CALCULATE(
    DISTINCTCOUNT(Usage_Events[user_id]),
    Usage_Events[event_type] IN {"prompt_submitted", "output_generated", "feature_completed", "output_exported"}
)
```
*Evaluate with `Calendar[week_number]` (or a single week's dates) in the
filter context — e.g. as a row in a matrix, or filtered by a week slicer.*

```dax
MAU 28D =
CALCULATE(
    DISTINCTCOUNT(Usage_Events[user_id]),
    Usage_Events[event_type] IN {"prompt_submitted", "output_generated", "feature_completed", "output_exported"},
    DATESINPERIOD(Calendar[date], MAX(Calendar[date]), -28, DAY)
)
```

```dax
Stickiness WAU/MAU = DIVIDE([WAU], [MAU 28D])
```

```dax
Feature Adoption Rate =
VAR AdoptedUsers =
    CALCULATE(
        DISTINCTCOUNT(Usage_Events[user_id]),
        Usage_Events[event_type] IN {"feature_completed", "output_exported"}
    )
RETURN
DIVIDE(AdoptedUsers, [Eligible Users])
```
*Evaluate with `Feature_Catalog[feature_name]` in context (e.g. a matrix row)
so `AdoptedUsers` is scoped to that feature via the active relationship.*

```dax
Core Feature Adoption Rate =
CALCULATE([Feature Adoption Rate], Feature_Catalog[core_feature_flag] = TRUE())
```
*As a standalone KPI card (no feature in context), this reads as "% of
eligible users who completed/exported at least one core feature."*

```dax
Median Time to Value Hours = MEDIAN(Users[Hours To Value])
```

```dax
Training Completion Rate =
VAR Assigned = CALCULATE(COUNTROWS(Users), NOT ISBLANK(Users[training_assigned_date]))
VAR Completed = CALCULATE(COUNTROWS(Users), NOT ISBLANK(Users[training_completed_date]))
RETURN
DIVIDE(Completed, Assigned)
```

```dax
Estimated Minutes Saved =
CALCULATE(
    SUM(Usage_Events[estimated_minutes_saved]),
    Usage_Events[event_type] IN {"feature_completed", "output_exported", "output_generated"},
    Usage_Events[successful_completion_flag] = TRUE()
)
```
*Disclaimer to render next to this measure everywhere it's used: "Modeled
estimate from synthetic data — not validated ROI."*

```dax
Estimated Hours Saved = DIVIDE([Estimated Minutes Saved], 60)
```

```dax
Recommendation Rate =
VAR TotalFeedback = CALCULATE(COUNTROWS(Feedback), NOT ISBLANK(Feedback[would_recommend_flag]))
VAR Recommended = CALCULATE(COUNTROWS(Feedback), Feedback[would_recommend_flag] = TRUE())
RETURN
DIVIDE(Recommended, TotalFeedback)
```

```dax
Average Feedback Rating = AVERAGE(Feedback[rating_1_to_5])
```

```dax
Dormant Users =
VAR MaxEventDate = CALCULATE(MAX(Usage_Events[event_timestamp]), ALL(Usage_Events))
VAR ActiveRecently =
    CALCULATETABLE(
        VALUES(Usage_Events[user_id]),
        Usage_Events[event_type] IN {"prompt_submitted", "output_generated", "feature_completed", "output_exported"},
        DATESINPERIOD(Calendar[date], MaxEventDate, -28, DAY)
    )
RETURN
CALCULATE(
    COUNTROWS(Users),
    Users[Is Activated] = TRUE(),
    NOT Users[user_id] IN ActiveRecently
)
```

```dax
Dormancy Rate = DIVIDE([Dormant Users], [Activated Users])
```

```dax
Week 1 Retention =
VAR CohortUsers = VALUES(Users[user_id])
VAR CohortSize = CALCULATE(COUNTROWS(Users), NOT ISBLANK(Users[Activation Week]))
VAR TargetWeek = SELECTEDVALUE(Users[Activation Week]) + 1
VAR ActiveInTargetWeek =
    CALCULATE(
        DISTINCTCOUNT(Usage_Events[user_id]),
        Usage_Events[event_type] IN {"prompt_submitted", "output_generated", "feature_completed", "output_exported"},
        Calendar[week_number] = TargetWeek,
        Usage_Events[user_id] IN CohortUsers
    )
RETURN
DIVIDE(ActiveInTargetWeek, CohortSize)
```
*Intended for a matrix/table with `Users[Activation Week]` on rows (one row
per cohort). `Week 4 Retention` is identical with `+ 4` in place of `+ 1`:*

```dax
Week 4 Retention =
VAR CohortUsers = VALUES(Users[user_id])
VAR CohortSize = CALCULATE(COUNTROWS(Users), NOT ISBLANK(Users[Activation Week]))
VAR TargetWeek = SELECTEDVALUE(Users[Activation Week]) + 4
VAR ActiveInTargetWeek =
    CALCULATE(
        DISTINCTCOUNT(Usage_Events[user_id]),
        Usage_Events[event_type] IN {"prompt_submitted", "output_generated", "feature_completed", "output_exported"},
        Calendar[week_number] = TargetWeek,
        Usage_Events[user_id] IN CohortUsers
    )
RETURN
DIVIDE(ActiveInTargetWeek, CohortSize)
```

For the **weeks 0-8 retention heatmap** on Report Page 2, build a small
disconnected "Weeks Since Activation" table (`GENERATESERIES(0, 8, 1)`,
one column `[WeeksOut]`) via Modeling → New Table, and use a general-purpose
version of the same measure:

```dax
Retention % (heatmap) =
VAR CohortUsers = VALUES(Users[user_id])
VAR CohortSize = CALCULATE(COUNTROWS(Users), NOT ISBLANK(Users[Activation Week]))
VAR WeeksOut = SELECTEDVALUE('Weeks Since Activation'[WeeksOut])
VAR TargetWeek = SELECTEDVALUE(Users[Activation Week]) + WeeksOut
VAR ActiveInTargetWeek =
    CALCULATE(
        DISTINCTCOUNT(Usage_Events[user_id]),
        Usage_Events[event_type] IN {"prompt_submitted", "output_generated", "feature_completed", "output_exported"},
        Calendar[week_number] = TargetWeek,
        Usage_Events[user_id] IN CohortUsers
    )
RETURN
DIVIDE(ActiveInTargetWeek, CohortSize)
```
*Use this measure in a matrix with `Users[Activation Week]` on rows and
`'Weeks Since Activation'[WeeksOut]` on columns for the heatmap.*

```dax
Previous Week WAU =
CALCULATE([WAU], DATEADD(Calendar[date], -7, DAY))
```
*Requires `Calendar` to be marked as the model's date table (Modeling → Mark
as Date Table, using `Calendar[date]`) — this is what makes `DATEADD` valid.*

```dax
WAU Week-over-Week Change = [WAU] - [Previous Week WAU]
```

```dax
WAU WoW Change % = DIVIDE([WAU Week-over-Week Change], [Previous Week WAU])
```

```dax
Low Adoption Business Units =
VAR Threshold = 0.70
RETURN
COUNTROWS(
    FILTER(
        VALUES(Business_Unit[business_unit_name]),
        CALCULATE([Activation Rate]) < Threshold
    )
)
```
*Threshold (70%) is a chosen reference point for this portfolio project, not
an externally validated benchmark — adjust freely.*

```dax
Top Barrier Category =
VAR RankedBarriers =
    ADDCOLUMNS(
        FILTER(VALUES(Feedback[barrier_category]), Feedback[barrier_category] <> "No barrier reported"),
        "@Mentions", CALCULATE(COUNTROWS(Feedback))
    )
RETURN
MAXX(TOPN(1, RankedBarriers, [@Mentions], DESC), Feedback[barrier_category])
```

```dax
Executive Narrative =
VAR ActRate = [Activation Rate]
VAR WoW = [WAU Week-over-Week Change]
VAR TrendWord = IF(WoW >= 0, "up", "down")
VAR TopBarrier = [Top Barrier Category]
RETURN
"This period, activation rate is " & FORMAT(ActRate, "0.0%") &
", weekly active users are " & TrendWord & " " & FORMAT(ABS(WoW), "#,0") &
" vs. last week, and the most commonly reported barrier is """ & TopBarrier &
""". (Synthetic data — association only, not a causal claim.)"
```
*This is the dynamic one-sentence takeaway for Report Page 1. Its wording
changes automatically as slicers change the filter context.*

## 5. A note on what "working DAX" means here

Every measure above follows correct, idiomatic DAX syntax (`CALCULATE`
context transition, `DIVIDE` for safe division, `DATESINPERIOD`/`DATEADD`
time intelligence against a marked date table, `SELECTEDVALUE` for
matrix-row context). They were designed and cross-checked against the
equivalent, already-executed pandas (`src/analysis.py`) and SQL
(`sql/02_adoption_metrics.sql`) logic so the three should agree on the
underlying dataset. They have **not** been executed inside a live Power BI
session as part of this repository (see `powerbi/BUILD_INSTRUCTIONS.md` for
why the `.pbix` itself is a manual, not automated, deliverable) — when you
build the model, paste these in one at a time and check each against the
Python/SQL output for the same metric as your own validation step.
